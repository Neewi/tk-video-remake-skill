# TikTok 视频复刻与 Symphony 交付

## 目标与边界

只执行两个阶段：

1. 完整解析源视频，提交一份低噪音、可直接编辑的“原视频脚本 + 独立 BASE 原样复刻脚本 + 3 个 M2 与 2 个 M3 变体覆盖层”，等待人工浏览、修改并选择一个分支。
2. 只为本次选中的 BASE 或单个 Vxx 生成四张分镜宫格备选图、可选裁剪图和一段包含人物/环境文字锚点的视觉自足 Symphony 提示词；完成后允许用户继续选择其他分支。

不要继续生成 Symphony 视频、质检回传片段、剪辑、配音、合成字幕或输出最终成片。

## 默认模式

- 默认使用 `TARGET_PRODUCT_REMAKE`：保留源片的人物可见外观、造型、场景、构图、动作、运镜、节奏和广告机制，把源片所有商品相关对象替换为目标 SKU。
- 默认执行“忠实复刻 + 最小转化强化”：先保留源片已成立的钩子、广告机制和转化路径；只有在不改变事实、镜头语义和用户要求时，才强化前 3 秒商品可见性、动作起点、口播清晰度和视听节奏。
- 用户指定 SKU 时使用该 SKU；用户未指定时读取 `catalog.yaml.default_sku`。
- 只有用户明确说“保留源片商品”或“完全忠实原产品”时，才使用 `SOURCE_FAITHFUL`，任务标识为 `SOURCE`。
- 商品相关对象包括平板、配件、保护套、触控笔、键鼠、线材、屏幕、包装盒、产品 Logo、产品颜色和套装关系。
- 只替换源片中实际出现或经人工批准新增的商品对象。产品资料库中存在但源片未出现的配件，不得自动加入画面。

## 不可违反的规则

- 区分“源片事实”“目标产品事实”“建议改写”和“人工定稿”，不得混写。
- 不识别源片人物真实身份，不从外观推断真实族裔、国籍或其他敏感属性；执行稿中的族裔与地域只作为虚构演员和虚构场景的生成约束。
- 目标商品外观只由产品资料库图片定义；参数、赠品、功能、价格、折扣、库存和活动只使用 `product.yaml` 或用户本轮明确确认的事实。
- 包装参考图只定义包装外观，不得用包装上的颜色勾选、图片或文字推断实物配置。
- 源台词与目标商品事实冲突时，内部完成核对，并在执行稿中使用最小安全改写。人类审核文件只显示与当前执行内容直接相关的简短事实边界；不要输出大段冲突表、证据表或勾选表。只有确实无法安全定稿的冲突才作为单一阻塞项显示。
- 听不清或看不清时标注 `[听辨不确定]` / `[无法辨认]`，不得合理化补齐。
- 对年龄只做最小生成适配：源片分析不得臆测真实年龄；若人物具有明显儿童外观，BASE、Vxx、宫格和视频提示词根据原场景改写为“青少年”或“高中生”，不写具体年龄、`18 岁以上`、`成年人`或其他会使外观明显成熟的标签。尽量保留角色关系、服装风格、动作、构图和节奏。
- 生成内容不得使用“儿童、小孩、小朋友、婴儿、幼儿、未成年”等直接儿童标签；允许并优先使用“青少年”或“高中生”。无人物视频明确写“画面中不出现人物”。
- BASE、Vxx、宫格和 Symphony 提示词中的虚构人物必须明确选为美国白人或美国黑人，不出现亚洲面孔。每个主要人物首次出现时固定一种选角，跨镜头保持一致；多人或背景人群可由美国白人与美国黑人共同组成，不用含混的“白人或黑人”让同一人物随机漂移。
- 所有生成场景必须完成美式本地化，同时保持源片的场景功能、空间关系、动作和镜头语义：家庭内景使用当代美式住宅装修，街头使用美式城市或郊区街景，校园使用美式高中环境，其他可识别场所使用对应的美国环境视觉语言。
- 四张宫格分镜都必须使用批准后的目标商品，不得残留源片商品、配件或包装。
- Symphony 最终只交付一段完整提示词，对应一次整条视频生成；不得按镜头拆成多个提示词文件。
- Symphony 提示词必须要求一次生成完整画面和完整音频，包括人物口播、画外音、环境声、BGM 和音效；不得依赖后期补音或剪辑。
- Symphony 提示词必须视觉自足：用简洁的“人物外观锚点”和“环境视觉锚点”写清跨镜头稳定特征，再用完整时间线写清画面、动作、摄影机和结束状态；即使没有宫格、只配合产品图也能成立。宫格存在时只加强具体构图、景别、站位和瞬时动作，不得与文字锚点冲突。不得引用产品图文件名或依赖不确定的图片编号，目标商品身份仍直接写成明确文字约束。
- Symphony 提示词必须直接面向视频生成模型，使用画面、摄影、动作和声音制作语言；不得出现“本提示词”“唯一依赖”“必传”“用户”“上传”“可选参考图”“推荐参考图”“文件名”“已批准/未批准”“审核”“事实边界”“交付”等面向人类工作流的元话术。
- 不得以规避平台重复内容检测为目标。只提示来源、人物、音乐和投放授权风险，不静默改变已批准内容。

## 工作区配置

按以下优先级定位 `workspace.yaml`：

1. 脚本的 `--workspace <path>` 参数。
2. 环境变量 `TIKTOK_VIDEO_REMAKE_WORKSPACE`。
3. 从当前工作目录逐级向上查找 `workspace.yaml`。

配置文件定义：

- 产品资料库：`product_library`
- 任务输出根目录：`output_root`
- Symphony 单段时长上限：`generation.max_clip_seconds`

相对路径一律相对于 `workspace.yaml` 所在目录解析；绝对路径继续兼容。找不到配置时报告上述三种定位方式并询问，不在其他位置擅自创建产品库。需要新配置时以 `assets/workspace.example.yaml` 为模板。

运行脚本前确认 Python 环境可导入 PyYAML 与 Pillow，并确认系统可执行 `ffmpeg` 和 `ffprobe`。不得把本机虚拟环境、`.tools` 或模型缓存打包进 Skill。

## 开始任务

1. 确认源视频可读，逐字记录用户本轮要求。
2. 确定模式和 SKU。默认读取 `catalog.yaml.default_sku`；运行 `scripts/validate_product_library.py`。
3. 完整读取 `references/product-library.md`，列出实际使用的产品事实、身份图、配件图、包装图和缺失角度。
4. 用 `scripts/create_run.py` 建立任务目录；目标商品模式使用 SKU，源商品模式使用 `SOURCE`。
5. 复制源视频到 `00-input/`，不得移动或覆盖原文件。
6. 运行 `scripts/validate_generation_duration.py --video <源视频>`，确认源视频时长不超过 `generation.max_clip_seconds`；校验失败时停止并请用户提供不超限的源片，不得静默裁切或加速。
7. 运行 `scripts/prepare_video.py`，生成元数据、候选切点、密集帧、场景帧、联系表和分析音轨。
8. 完整读取 `references/video-analysis.md`、`references/variant-scripts.md` 与 `references/generation-safety.md` 后开始阶段一。

## 阶段一：脚本解析与人工审核

只输出一个主要审核文件：`01-analysis/script-review.md`。

阶段一的目标是让人类直接看脚本和改脚本，不是阅读分析报告。完整读取 `references/video-analysis.md`、`references/variant-scripts.md` 与 `references/generation-safety.md`，并严格遵守以下人类界面契约：

1. 文件开头用三行以内说明：直接修改“复刻执行脚本”或任意变体；每次只执行一个脚本；修改后回复“继续原样脚本”或“继续 V01/V02…”。
2. 第一部分是“原视频脚本（只读参考）”。按真实镜头顺序直接写画面、动作/运镜、逐字原口播、字幕/OCR、音频和结束状态。不要先放摘要、证据表、切镜表或分析方法。
3. 第二部分是“复刻执行脚本（原样复刻，独立可执行）”，标识为 `BASE`。它是完整脚本，不依赖变体母版；按相同镜头顺序写目标画面、口播、音频和切镜/结束状态，并执行“忠实复刻 + 最小转化强化”。
4. 第三部分是“变体母版”和默认 5 个 `V01–V05` 覆盖层：`V01–V03` 为 M2 保钩子中变体，`V04–V05` 为 M3 大变体；用户本轮明确指定其他数量或配比时服从用户。每个变体写清差异等级、保护项、变化轴、逐镜覆盖、必要适配和保持不变，不机械复制完整 BASE。
5. 最后一部分只放简短的“商品参考与事实边界”：实际使用的参考图、用户本轮确认的事实，以及执行稿中不得使用的未证实声称。使用短列表，不使用宽表。
6. 不输出镜头勾选框、“人工决定”字段、逐项批准选项、重复的完整口播汇总、冗长产品事实、分析证据、自检过程或模板说明。
7. 解析证据、元数据、转录文件和联系表保留在 `01-analysis/prepared/`，不要把它们大段复制到人类审核文件。
8. 若有无法通过安全默认值解决的阻塞冲突，在文件最上方列一个简短“继续前必须确认”区；没有阻塞项就完全省略该区。

把 `script-review.md` 交给用户后停止，不生成分镜。用户可以直接编辑文件，也可以不修改。

当用户要求继续某个脚本时：

1. 必须重新从磁盘读取 `script-review.md`，不得依赖先前对话中的脚本副本。
2. 按 `references/variant-scripts.md` 将用户口令归一化为 `BASE` 或一个 `Vxx`。存在变体时，用户只说“继续”则询问选择；没有变体时继续兼容为 BASE。每次只执行一个分支。
3. 选择 BASE 时只使用完整 BASE，忽略所有变体；选择 Vxx 时使用当前 BASE + 变体母版 + 该 Vxx 明确覆盖项，忽略其他变体。
4. 将所选分支的当前磁盘内容视为人工批准稿，不要求逐镜勾选、粘贴修改或重复批准，也不覆盖人工修改。
5. 运行 `scripts/validate_generation_duration.py --script-review <script-review.md> --script-id <BASE-or-Vxx>` 校验所选分支时长；失败时停止并请用户压缩该分支，不得自动删词、加速或裁切。
6. 只有所选分支仍存在明确的 `[待确认事实]`、无依据产品声称、不可实现动作或不清楚的覆盖项时，才用一个简短问题阻止继续；否则立即进入阶段二。
7. 运行 `scripts/manage_delivery_branch.py start <run-dir> <script-review.md> <BASE-or-Vxx>`，建立独立分支目录并记录当前审核文件版本。

## 阶段二：宫格分镜与单条 Symphony 提示词

完整读取 `references/storyboard-prompts.md` 与 `references/generation-safety.md`；所有输出只对应本次选中的 `BASE` 或单个 `Vxx` 有效脚本。

1. 从批准脚本提取 6–12 个视觉关键状态，而不是简单按镜头数取帧。默认优先使用 9 宫格；关键状态不超过 6 个时可用 6 宫格，超过 9 个时使用 12 宫格。
2. 源视频关键帧定义人物、场景、构图、动作、灯光和空间关系；目标产品图定义平板、配件和包装身份。
3. 使用可用的图像编辑/生成能力分别生成 A1、A2、B1、B2 四张完整宫格备选图；每张图都一次生成完整宫格，不逐格生成或拼接独立最终分镜。四张都必须通过检查后再交付。
4. A1、A2 忠实执行所选 BASE/Vxx，并优先保留源片构图、机位、景别、动作节奏和自然 UGC 质感；Vxx 已覆盖的人物或场景不得还原成源片值。B1、B2 在相同批准语义下强化前 3 秒主体可见性、关键动作、景别落差和画面张力，不得新增剧情、卖点、商品事实或不可连续的动作。
5. 四张宫格中所有商品相关对象都必须换成批准 SKU；人物、场景、格数、编号、关键状态、时间线语义和非商品道具保持一致，确保任意一张都能配合同一份 Symphony 提示词。
6. 保存到 `02-storyboard/<BASE-or-Vxx>/storyboard-grid-a1.png`、`storyboard-grid-a2.png`、`storyboard-grid-b1.png` 与 `storyboard-grid-b2.png`。宫格编号放在格子边框或留白中，不覆盖主体。
7. 分别运行 `scripts/crop_storyboard_grid.py`，机械裁到该分支的 `crops-a1/`、`crops-a2/`、`crops-b1/` 与 `crops-b2/`；裁剪不属于重新生成。
8. 输出该分支唯一视频提示词 `03-symphony/<BASE-or-Vxx>/symphony-prompt.txt`。它必须是一段可整体复制的纯文本，对应一次整条视频生成。
9. 在提示词中增加简洁的“人物外观锚点”和“环境视觉锚点”，只写跨镜头稳定、且四张宫格共有的身份与环境特征；不要在锚点中写精确站位、临时姿态、瞬时表情、具体景别或主体画面占比。宫格存在时由宫格锁定这些动态构图细节，没有宫格时由完整时间线锁定。
10. 提示词按时间码写出不依赖宫格也能执行的完整画面与音频时间线，包括人物称谓、场景、动作起点/过程/结束、摄影机、真实切镜、完整逐字口播、口型/画外音关系、环境声、BGM 和音效；可在相应时间段附带宫格编号作为增强参考，但不得让句意依赖宫格才能成立。
11. 明确要求输出正常全屏视频，不得生成宫格、分屏、边框、格号或 storyboard 画面。
12. 交付前必须运行 `scripts/validate_symphony_prompt.py 03-symphony/<BASE-or-Vxx>/symphony-prompt.txt`；校验未通过时修正提示词，不得绕过或交付。
13. 首次直接同时展示 A1、A2、B1、B2 四张宫格和 `symphony-prompt.txt`，不增加人工批准门。说明用户可任选一张宫格增强构图稳定性，也可只使用提示词配合产品图；若不满意，可回复“宫格 A1/A2/B1/B2 + 第几格 + 具体问题”，随后生成一张新的完整宫格备选并保持其他格与时间线稳定。仅视觉修正不重写 Symphony 提示词；只有反馈改变人物稳定特征、环境稳定特征、镜头语义、时间码、台词或商品事实时才同步更新提示词。

展示本分支四张宫格备选图，并提供其 `symphony-prompt.txt`；说明 A1/A2 更忠实、B1/B2 更有转化张力，宫格可用于加强构图稳定性，不使用宫格时提示词也可配合产品图独立使用。运行 `scripts/manage_delivery_branch.py complete <run-dir> <script-review.md> <BASE-or-Vxx>`，在确认四张宫格和提示词存在后标记本分支完成。然后列出审核文件中仍可继续的 BASE/Vxx，并提示用户可以回复“继续原样脚本”或“继续 Vxx”增量生成另一分支。本次分支到此结束，不自动生成其他分支。
