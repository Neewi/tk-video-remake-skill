# 视频解析与低噪音脚本审核规范

## 1. 内部分析顺序

先完成证据分析，再写人类审核文件：

1. 读取 `metadata.json`，确认时长、画幅、帧率、音轨和编码。
2. 查看候选切点、密集帧和联系表，人工确认真实切镜。
3. 检查 0–3 秒钩子、人物口型、动作、商品、包装、字幕、价格和 CTA。
4. 听完整音频，区分同期声、画外音、环境声、BGM 和音效。
5. 转录可读文字；听不清写 `[听辨不确定：候选词]`，看不清写 `[无法辨认]`。
6. 读取目标商品事实和参考图，逐对象核对平板、配件、包装、屏幕及物理动作。
7. 为无事实依据的源声称准备最小安全改写；不要把建议冒充源片原文。
8. 检查前 3 秒钩子与全片“钩子 → 商品/问题 → 展示/证明 → 用户利益 → CTA”路径，记录可在不改变事实和核心广告机制时完成的最小强化。
9. 检查人物年龄外观：源片只记录可观察外观，不推断真实年龄；明显儿童外观的人物在生成稿中按 `generation-safety.md` 最小改写为高中生，不改成 18 岁以上的成年人外观。
10. 区分源片事实与生成设定：源片不推断真实族裔或国籍；BASE/Vxx 按 `generation-safety.md` 为虚构人物指定美国白人或美国黑人选角，并把环境视觉本地化为对应的美式家庭、街头、校园或其他美国场所。

以上是内部工作。元数据、证据帧、转录和详细核对留在 `01-analysis/prepared/`，不要把分析过程大段复制到 `script-review.md`。

## 2. 真实切镜

只有以下证据才建立新镜头：

- 时间或空间明显跳变。
- 人物姿态、商品位置或背景在相邻帧中不可能连续。
- 明确硬切、叠化、遮挡转场、速度转场或匹配剪辑。

连续镜头内的推、拉、摇、移和动作阶段保持在同一镜头。时间精确到 0.1 秒，无法确认时给区间。

## 3. 阶段一文件界面

`01-analysis/script-review.md` 必须让人打开后立即看到可读、可改的脚本。顺序固定为：

1. 三行以内的编辑说明。
2. 少量基本信息。
3. `原视频脚本（只读参考）`。
4. `复刻执行脚本（原样复刻，独立可执行）`，标识为 BASE。
5. `变体母版`与 `V01–Vxx` 变体覆盖层。
6. 简短的 `商品参考与事实边界`。

不要在脚本前放摘要、证据表、商品映射表、冲突表、审核清单、自检结果或分析方法。不要使用勾选框或逐镜“人工决定”字段。

### 文件开头

`REVIEW_INCREMENTAL` 使用类似以下说明，控制在三行以内：

```markdown
> 请直接修改“复刻执行脚本”或任意变体；每次只执行一个脚本。
> 修改后回复“继续原样脚本”或“继续 V01/V02…”；届时会重新读取本文件，并执行所选分支的当前内容。
```

`DIRECT_BATCH` 改用类似以下说明：

```markdown
> 本文件是 BASE 与 V01–V05 六版直出的执行记录。
> 系统将按顺序为每个分支生成独立 B1 宫格和 Symphony 提示词；如中断，可从首个未完成分支继续。
```

基本信息只保留：模式、目标 SKU、源片/目标时长、画幅、真实镜头数和商品替换总原则。只有执行稿做了超出商品替换与事实改写的转化强化时，再用一行简述实际改变；只有实际把明显儿童外观人物调整为高中生时，再增加一行“生成描述适配”，说明人物保持年轻感且场景、关系、动作、构图和节奏不变。另用一行简述虚构演员的美国白人/黑人选角与场景美式本地化。

## 4. 原视频脚本

这一部分是源片事实，只读参考。逐镜使用以下紧凑格式：

```markdown
## S01｜0.0–2.7 秒｜<镜头目的>

**画面与动作**

<人物、场景、商品、动作时间线、构图和运镜，写成自然段。>

**原口播**

> <逐字原文；听不清处保留不确定标记。>

**字幕/OCR**

<只写实际可见文字；没有则省略整个字段。>

**音频**

<同期声/画外音、语气、环境声、BGM 和音效。>

**结束与切镜**

<结束状态和真实转场。>
```

规则：

- 直接写原片，不夹带目标商品或改写建议。
- 对人物年龄只写可观察到的外观；不得在原视频脚本中臆测真实年龄。明显年幼写“明显儿童外观的人物”，无法判断写“年龄外观不确定的人物”。
- 中文翻译仅在确有助于审核时紧跟原口播，不重复解释。
- 没有字幕、BGM 或音效时，用一句话说明，不展开证据。
- 不另写全片摘要、切镜总表或重复的完整口播汇总。

## 5. 复刻执行脚本

这一部分标题固定为 `# 复刻执行脚本（原样复刻，独立可执行）`，分支标识为 `BASE`。它是人工可直接修改的完整生成脚本，不依赖变体母版或任何 Vxx。镜头编号和时间范围与原视频脚本一一对应：

```markdown
## S01｜0.0–2.7 秒

**执行画面**

<保留项、目标商品替换、动作、构图、运镜和必要约束。>

**执行口播**

> <可直接生成的最终候选台词。>

**执行音频**

<口型/画外音、说话方式、环境声、BGM 和音效。>

**结束与切镜**

<结束状态和转场。>
```

执行稿规则：

- 默认保留源人物可见外观、场景、构图、动作、运镜、节奏和广告机制。
- 若源片人物具有明显儿童外观，无论场景均写“高中生”；保持年轻面部比例、角色关系、服装风格、动作、构图、机位和节奏，不写具体年龄、`18 岁以上`或`成年人`。年龄外观不确定时不做大幅外形改造，仍使用“高中生”描述。
- 执行稿中的人物均为虚构演员。每个主要人物首次出现时明确固定为“美国白人”或“美国黑人”，跨镜头不得改变；多人和背景人群可明确由美国白人与美国黑人组成，不出现亚洲面孔。
- 保持源片场景功能和空间关系，但把视觉环境本地化为美国：客厅、卧室、厨房等使用当代美式家庭装修，街头使用美式城市或郊区街景，教室和校园使用美式高中环境，其他场所使用对应的美国建筑、陈设和公共空间语言。
- 执行“忠实复刻 + 最小转化强化”：先保留源片已成立的钩子和转化路径，再检查 0–3 秒是否至少清晰呈现目标人群、问题/反差、商品、关键动作、结果或利益点中的一项。
- 源片钩子已经明确时，保留其语义、出现时间和视听结构；钩子较弱时，只通过提前同一镜头内的商品或关键动作、删除无信息停顿、缩短首句、明确注意力主体、强化已有声音强调等方式做最小调整。
- 每个镜头至少承担钩子、问题、展示、证明、用户利益或 CTA 中一项功能；优先删除无信息重复，不以频繁切镜、异常语速或堆砌音效代替内容推进。
- 景别、角度、动作和运镜必须服务于商品识别、动作理解或情绪推进；复杂商品结构和手部交互应给足看清的时间。
- 不得为增强转化而虚构价格、性能、稀缺性、痛点、评价、使用结果或戏剧冲突，也不得静默改变源片核心创意、镜头语义和用户要求。
- 把源片实际出现的商品对象替换为目标 SKU；不自动加入未出镜配件。
- 对未证实的性能、尺寸、兼容性、价格、折扣、库存、赠品和活动声称使用最小安全改写。
- 参考图不足但可采用中性默认值时，直接采用安全默认值，不制造阻塞。例如缺少屏幕图时使用中性无文字界面。
- 用户本轮明确确认的事实可以直接进入执行稿，并在末尾事实边界中用一行记录来源。
- 不在每个镜头后重复写冲突分析、参考图列表或人工决定。
- 不在末尾重复汇总完整连续口播；阶段二按镜头顺序拼接执行口播。

## 6. 变体母版与变体方案

完整读取 `references/variant-scripts.md`。在 BASE 之后生成一个变体母版和默认 5 个 `V01–V05` 方案：`V01–V03` 为 M2 保钩子中变体，`V04–V05` 为 M3 大变体；用户本轮明确指定其他数量或配比时服从用户。

- BASE 必须保持独立完整，不能写成“参照变体母版”。
- 变体只写相对 BASE 的覆盖项，不复制完整脚本。
- 每个变体写明差异等级、保护项、主要变化、变化轴、逐镜覆盖、必要适配和保持不变。
- 三个 M2 分别选择不同主变化轴，采用“一个主变化轴 + 一个配套变化轴”，保护前 3 秒钩子骨架、核心动作、情绪曲线和转化路径。
- 两个 M3 分别使用不同结构概念，至少改变两个结构轴；允许在事实与时长范围内重构钩子表达、叙事视角、人物关系、场景—动作系统、镜头顺序或必要口播。
- 变体必须达到 `references/variant-scripts.md` 的最低镜头覆盖量，不得只靠选角、服装、灯光或背景装饰制造差异。
- 变体建议保留商品事实、目标受众问题、核心利益、商品证明作用和整体情绪强度，不为形成差异而虚构卖点或无关剧情。
- 所有内容都允许用户直接增删改；磁盘上的当前内容是后续唯一来源。

## 7. 商品参考与事实边界

文件末尾只保留三类短列表：

```markdown
# 商品参考与事实边界

## 本片使用的参考

- <对象>：<相对路径>，只定义<职责>。

## 用户本轮确认的事实

- <没有则省略整个小节。>

## 执行稿已避开的未证实声称

- <只列确实导致执行口播改变的源声称。>
```

不要复述整个 `product.yaml`。参考图包含未出镜配件时，明确“只定义指定对象，不把其他配件加入本片”。包装只定义包装外观，不证明实物颜色或套装内容。

## 8. 阻塞项

默认通过最小安全改写和中性视觉值产出可直接批准的执行稿。只有下列情况才在文件最上方增加 `继续前必须确认`：

- 目标商品无法完成源片核心物理动作，且没有不改变广告机制的安全替代。
- 产品图片和结构化事实直接冲突。
- 用户要求保留的具体声称缺少事实依据。
- 必需商品身份图缺失，无法可靠生成目标对象。

阻塞区只写：问题、推荐默认方案、用户需要确认的一句话。不要附长表。

## 9. 进入阶段二

`REVIEW_INCREMENTAL` 在交付 `script-review.md` 后停止。用户可以直接在文件中修改，也可以不修改。

收到继续指令后：

1. 重新从磁盘读取整个文件。
2. 按 `references/variant-scripts.md` 识别 `BASE` 或单个 `Vxx`；存在变体时单说“继续”只询问选择，不自行默认 BASE。
3. 选择 BASE 时只提取完整 BASE；选择 Vxx 时用 BASE + 变体母版 + 该 Vxx 覆盖项合成有效执行稿，忽略其他变体。
4. 将所选分支当前内容视为人工批准稿；不要求勾选、复制粘贴或再次口头批准，不覆盖人工修改。
5. 校验所选分支的时长、事实、动作可行性和覆盖项清晰度。
6. 若没有 `[待确认事实]` 或新的无依据产品声称，立即为该单一分支进入阶段二。
7. 若仍有阻塞，只问一个最短、最具体的问题。

`DIRECT_BATCH` 保存同样的完整脚本文件，但不等待选择；按 `references/run-modes.md` 的固定顺序逐个合成并执行六个分支。每次仍只把一个有效分支送入阶段二，防止不同 Vxx 内容互相污染。
